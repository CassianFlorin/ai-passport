# 电脑 USB 配置

个人首页应用通过现有的 USB Serial/JTAG 连接接收 Wi-Fi 和 AI 服务配置。配置网页在电脑上
运行，设备可以在尚未连接 Wi-Fi 时完成设置。页面资源全部随项目提供，不依赖云端配置服务，
也不需要手机。

## 打开配置页面

准备 Python 3，以及支持 Web Serial 的桌面浏览器，例如 Chrome 或 Edge：

```bash
python3 tools/usb_config.py
```

打开命令输出的本地地址，通常是 `http://127.0.0.1:8765/`。可以使用 `--port` 指定其他端口，
或者用 `--open` 打开默认浏览器。不支持的浏览器会提示改用兼容的桌面浏览器。

1. 开启设备电源，用可传输数据的 USB 线连接电脑。
2. 关闭占用设备端口的串口监视器、烧录程序及其他应用。
3. 点击连接按钮，在弹窗中选择 USB JTAG/serial debug unit。
4. 读取当前配置，填写 2.4 GHz Wi-Fi 名称和密码、对话服务的 OpenAI 兼容 Base URL 和
   API Key，并按需填写单独的语音服务和模型名称。
5. 保存。页面分别显示保存结果和 Wi-Fi 连接、获取 IP 的结果，网络状态会自动刷新。
6. 使用串口监视器或烧录工具前，先在页面中断开连接。

浏览器连接用于读写设置，不会烧录固件。不支持该 USB 协议的固件会超时，页面会提示更新。
打开网页本身不会打开串口，用户选择设备后才建立会话。设备保留已有的独立个人首页与三键操作。

模型列表由设备获取，而不是浏览器或服务器。Wi-Fi 连接后，页面通过 USB 向设备发送 `models`
请求，附带 Base URL，以及页面上输入的 API Key 或"使用已保存的 Key"的标记；设备自己请求
`GET {Base URL}/models`，只把模型 ID 传回页面。已保存的 Key 只会发给保存时的同一个 URL，
页面无法把它转发到其他地址。因此 API Key 不会经过任何网站，包括线上配置页。设备已保存
Key 且 Wi-Fi 已连接时，连接 USB 后会立即加载列表。

对话服务的列表用于对话模型；语音服务的列表（未设置语音服务时使用对话服务的列表）用于语音识别
和语音合成模型。已保存的模型保持选中；字段为空时自动选中适合该用途的第一个推荐模型（对话模型
可退而使用列表中的任意模型）。下拉框同时列出其他全部模型和手动输入。如果列表中没有语音识别或
语音合成模型，页面会提示该服务可能不支持语音接口。音色提供常用的 OpenAI 音色名称。设备只保留
不超过 64 字节、由字母、数字和 `._:/@+-` 组成的模型 ID，最多返回约 6 KB。不提供 `/models` 的服务
仍可手动填写。获取列表与一轮对话占用相同的内存，对话进行时会拒绝获取。

## 线上配置页

`tools/usb-config/` 是纯静态网站，可以发布到 Cloudflare Pages 等平台，让用户通过公开的 HTTPS
地址配置设备：

```bash
npx wrangler pages deploy tools/usb-config --project-name <project>
```

`tools/usb-config/_headers` 使用与本地服务器相同的安全响应头，包括 `connect-src 'none'`：页面
不发出任何网络请求，只与用户选择的 USB 设备通信。静态检查会核对两处策略一致。部署内容不含
服务器代码或秘密信息；发布仍需单独明确授权。本地 `python3 tools/usb_config.py` 服务仍可离线使用。

## 设备上的 AI 对话

在个人首页双击 OK 打开功能列表。第一项为 AI 对话，后面依次为系统状态和设置。
UP/DOWN 每次移动一项，到两端后不循环；单击 OK 进入，长按 OK 返回列表。
返回时保留此前选中的项目。

AI 对话页是连接 OpenAI 兼容云端服务的按键对讲客户端：

| 按键 | 作用 |
| --- | --- |
| OK | 开始一轮对话；再按一次发送录音。等待时取消；朗读时停止朗读并保留回复 |
| UP / DOWN | 滚动识别文字和回复 |
| 长按 UP | 清空对话历史（没有进行中的对话时） |
| 长按 OK | 返回列表；先取消进行中的对话 |

一轮对话的步骤：

1. 连接 `POST {语音 Base URL}/audio/transcriptions`，然后打开麦克风并显示"正在听"。
   录音时把 16 kHz 单声道 PCM 以分块传输的 multipart WAV 边录边传，最长 15 秒；
   短于 0.3 秒的录音会被丢弃。
2. 把识别文字连同最多两轮历史和要求简短回答的系统提示词，发送到
   `POST {对话 Base URL}/chat/completions`（`stream: false`）。
3. 显示回复，再以 `response_format: "wav"` 请求 `POST {语音 Base URL}/audio/speech`，
   边下载边播放 16 位 PCM，立体声混为单声道。扬声器静音时不请求语音。

DeepSeek 等只提供对话的服务没有语音接口，因此语音可以使用另一家服务（例如硅基流动或
OpenAI）。语音 Base URL 留空时沿用对话服务的地址和 API Key。每个请求携带所属服务的
`Authorization: Bearer <API Key>`，HTTPS 使用 ESP-IDF 证书包校验。
同一时间只有一个请求；它的任务、TLS 缓冲、8 KB 工作缓冲和 16 KB 录音环形缓冲
只在对话进行时分配。页面会指出失败的步骤：无法连接服务、API Key 无效（401/403）、
接口或模型不存在（404）、请求过多或额度不足（429）、服务端错误、回复格式不支持、
没有听清，以及内存或音频故障。服务返回的错误信息会写入日志，但不包含地址和
API Key。语音播放失败时，文字回复仍保留在屏幕上。

用于提示的连接状态快照只包含公开标志，没有网络名称、服务地址或凭证。界面读取快照时，
不会在持有 LVGL 锁期间进行 Flash 或无线操作。设置页的试听不会等待进行中的对话，
对话期间会提示暂不能试听。

## 配置项和限制

| 配置项 | 限制与行为 |
| --- | --- |
| Wi-Fi 名称 | 最多 32 个 UTF-8 字节；可以手动填写或从扫描结果选择 |
| Wi-Fi 密码 | 开放网络为空，否则为 8–63 个 UTF-8 字节，或 64 位十六进制密钥 |
| Base URL | 最多 384 个 ASCII 字节；仅支持 `http://` 或 `https://`，不接受查询参数、用户名、密码或片段。需包含 API 版本路径，例如 `https://api.openai.com/v1` |
| API Key | 最多 512 个 UTF-8 字节；以 Bearer 令牌发送给对话服务 |
| 语音 Base URL | 可选，规则与 Base URL 相同；用于语音识别和语音合成。留空则沿用对话服务 |
| 语音 API Key | 最多 512 个 UTF-8 字节；与其他秘密信息一样只允许写入 |
| 对话模型 | 最多 64 字节；留空使用 `gpt-4o-mini` |
| 语音识别模型 | 最多 64 字节；留空使用 `whisper-1` |
| 语音合成模型 | 最多 64 字节；留空使用 `tts-1` |
| 音色 | 最多 64 字节；留空使用 `alloy` |

密码和 API Key 只允许写入。读取配置时仅返回是否已经保存，不会返回原文。密码或令牌留空表示
保留原值；勾选对应的清除选项才会删除。更换 Wi-Fi 名称后，需要重新填写密码，或明确选择开放网络。

Wi-Fi 名称为空并明确清除密码时，会停用 Wi-Fi 连接。仅修改服务配置不会重新连接未改变的
Wi-Fi。设备正在连接网络时可能暂时无法扫描，此时仍然可以手动填写网络名称。

保存配置时不会访问 AI 服务，第一次对话才会验证 Base URL、API Key 和模型；获取 IP
只代表设备已经连接到路由器。服务需要接受分块传输的请求体，以及 RIFF 长度为
`0xFFFFFFFF`（长度未知）的 WAV 上传，并且语音接口需要返回 PCM WAV。旧固件保存的
`ws://` 或 `wss://` 地址仍可读取，但 AI 对话页会提示配置无效。

## 保存和恢复

应用把配置保存为 NVS 命名空间 `connection` 下的单个版本化数据项 `values_v3`，与声音设置
分开。旧固件的记录（先找 `values_v2`，再找 `values_v1`）读取时新增字段为空；第一次保存时
写入 `values_v3`，并在同一次提交中删除这两个旧键。存储操作成功后才更新运行中的配置。没有记录时使用默认值；记录损坏或版本不支持时
返回错误，不会静默擦除。用户明确保存后可以替换这类记录。

开机时使用已保存的 Wi-Fi 配置自动连接。断线后逐步增加重试间隔，最长为 30 秒，网页也提供
手动重新连接按钮。存储、Wi-Fi 和扫描操作都在 USB 工作任务中执行，不占用按键回调或 LVGL
任务。未配置网络时，无线功能只在扫描或应用网络配置时启动。

本功能不提供秘密信息加密。配置保存在设备现有的 NVS 分区中，不会执行整分区擦除，也不修改
分区布局。请勿发布 NVS 转储、设备配置或包含秘密信息的日志。

## 传输和验证

报文以 `@PASSPORT1` 前缀标识；响应数据中的 `protocol` 为 3。第 2 版增加了四个模型字段，
第 3 版增加了语音服务地址和只写的语音 API Key。请求使用有长度上限的制表符分隔字段、十六进制 UTF-8
数据和换行结束符。响应使用相同前缀，携带 JSON 对象与请求 ID。秘密字段为 `*` 时保留原值，
为空时清除。客户端忽略没有协议前缀的控制台日志；设备遇到超长或混入二进制零字节的请求时，
丢弃至下一个换行，行缓冲区为 4608 字节。

静态检查会测试实际 C 解析器，对版本化存储和迁移注入故障，测试 OpenAI 兼容的请求与响应处理，让网页客户端与 C 串口模拟端通信，
并验证本地服务器只开放随附页面资源，且线上响应头策略与之一致。网页客户端的主机测试需要 Node.js 20 或更高版本，
运行页面服务只需要 Python 3。

```bash
./tools/validate.sh --static
./tools/validate.sh
```

真机验收仍需使用已经验证的固件，并取得明确的烧录许可。需要检查 USB 授权、反复连接和断开、
Wi-Fi 扫描、错误密码恢复、成功获取 IP、重启后的配置保留、密码与令牌的保留和清除，以及首页、
按键、音频同时工作的表现。AI 对话需要用实际使用的服务验证：完整的一轮对话、语音音质、
长回复与滚动、各阶段取消、错误 API Key 与模型、上传途中断网、静音，以及每轮结束后
日志中记录的最低可用内存。
